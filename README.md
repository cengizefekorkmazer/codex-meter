# CodexMeter

A macOS menu bar app for monitoring your Codex usage limits in real time.

CodexMeter runs locally, talks to the official `codex` CLI's app-server over
JSON-RPC, and shows your current 5-hour and weekly usage windows. It never
reads or stores your OpenAI credentials — authentication is owned by the Codex
CLI. (If you choose API-key sign-in, the key you paste is forwarded once to the
local Codex app-server and never written to disk by CodexMeter.)

## Features

- 5-hour and weekly usage windows visible at a glance in the menu bar
- Three menu bar display modes: icon only, icon + percentage, or `5h | 7d`
- Live updates pushed by the Codex app-server (no constant polling)
- Fallback polling every 5 minutes if no push arrives
- Auto-reconnect with exponential backoff if the app-server exits
- Sleep / wake recovery
- ChatGPT login flow (including device-code fallback) handled in-app
- Notifications when usage crosses configurable thresholds (50% / 75% / 90% / 95% / 100%)
- Launch at login (via `SMAppService`)
- Zero telemetry, no analytics, no network calls beyond the local Codex CLI

## Requirements

- macOS 13.0 (Ventura) or later
- [Codex CLI](https://developers.openai.com/codex/cli) — install with `brew install codex` or `npm i -g @openai/codex`
- A ChatGPT account signed in to the Codex CLI

CodexMeter checks the standard install locations (`/opt/homebrew/bin/codex`,
`/usr/local/bin/codex`) and falls back to `which codex`. You can also pin a
custom path in **Settings → General**.

## Installation

Pre-built signed releases will be published once the app reaches v0.4. Until
then, build from source — see below.

### Building from source

You need Xcode 15+ installed (not just Command Line Tools). The project file is
generated by [xcodegen](https://github.com/yonaskolb/XcodeGen):

```bash
# one-time tooling
brew install xcodegen

# clone & generate
git clone https://github.com/<you>/codex-meter.git
cd codex-meter
xcodegen generate

# build (use DEVELOPER_DIR if xcode-select still points to CLT)
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project CodexMeter.xcodeproj -scheme CodexMeter \
             -configuration Release build

# the built .app lands in DerivedData; open it directly:
open ~/Library/Developer/Xcode/DerivedData/CodexMeter-*/Build/Products/Release/CodexMeter.app
```

To regenerate the app icons after editing `scripts/generate_icons.swift`:

```bash
swift scripts/generate_icons.swift
```

## How it works

```
CodexMeter.app
    │
    ▼ spawns child process
codex app-server --listen stdio://
    │
    ▼ JSON-RPC 2.0 (line-framed, one object per line)
    │   initialize        → handshake
    │   initialized       → notification
    │   account/read      → identity + plan
    │   account/rateLimits/read     → usage snapshot (5h, weekly)
    │   account/rateLimits/updated  → server push when usage changes
    │   account/login/*  / account/logout
    │
    └─ menu bar + popover UI
```

CodexMeter does **not** read `~/.codex/auth.json` or any token file directly.
All authentication is handled by the Codex app-server, which CodexMeter only
queries via JSON-RPC.

## Architecture

```
CodexMeter/
├─ App/                       App entry, AppDelegate, AppState
├─ Core/
│  ├─ Codex/                  CodexBinaryResolver
│  │                          CodexAppServerProcess  — child process owner
│  │                          JSONRPCClient          — actor, line-framed RPC
│  │                          CodexAppServerClient   — high-level API
│  │                          CodexProtocolTypes     — Codable RPC shapes
│  ├─ Models/                 RateLimitSnapshot/Window, AccountState,
│  │                          ConnectionState, AppError, AppSettings,
│  │                          DisplayMode
│  └─ Services/               LaunchAtLoginManager, NotificationService
└─ UI/
   ├─ MenuBar/                StatusItemController (3 display modes)
   ├─ Popover/                PopoverView, BucketSection, WindowRow
   ├─ States/                 InstallCodexView, SignedOutView,
   │                          SigningInView, StartupView, ErrorView
   ├─ Settings/               TabView + 4 panels
   └─ Components/             ColorTheme
```

`AppState` derives an `AppPhase` enum from the current account / connection /
binary-presence state, and `PopoverView` switches on it to render the right
screen.

## Running the tests

The test target covers RPC encoding/decoding (`RateLimitWindow`,
`RateLimitsReadResult`, `CodexAccount` / `LoginAccountResponse` discriminated
unions, the generic `JSONRPCIncomingMessage` parser), `AppPhase` derivation,
and notification-throttling logic.

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project CodexMeter.xcodeproj -scheme CodexMeter \
             -destination 'platform=macOS' test
```

52 tests, no live `codex` process required.

## Privacy

- CodexMeter does not collect analytics.
- It does not run a backend server.
- It does not transmit your Codex usage data anywhere — all RPC traffic stays
  between CodexMeter and the local `codex` child process.
- It does not read or store your OpenAI tokens.

The only data persisted on disk is your `AppSettings` (display mode, polling
interval, notification thresholds, etc.) in `~/Library/Preferences/`.

When **Debug mode** is enabled (Settings → General), JSON-RPC traffic is
appended to `~/Library/Caches/CodexMeter/debug.log`. Disable it to stop
logging. API keys, OAuth tokens, and auth URLs are redacted from every line
before it is written, and the file is created mode 0600 and never auto-uploaded.
It does still record your account email and usage history, so treat it as
private if you share it.

## Status

This is pre-release software. The Codex app-server is itself marked
**experimental** by the Codex CLI — the protocol may change between Codex
releases. CodexMeter is pinned-tested against:

```
codex-cli 0.133.0
```

If a future Codex release changes a field name or method, CodexMeter will fail
gracefully (showing an error state) rather than crashing.

## Contributing

PRs welcome. Conventions:

- Keep the JSON-RPC transport (`Core/Codex/`) isolated from UI code.
- Don't read `~/.codex/auth.json` or any token file directly.
- No external analytics without a discussion in an issue first.
- Add tests for protocol decoding and rate-limit normalization when changing
  those modules.
